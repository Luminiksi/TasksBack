# TaskFlow REST API Specification

## 1. Назначение

Этот документ описывает REST API приложения TaskFlow: доступные эндпоинты, HTTP-методы, форматы запросов и ответов, а также возможные HTTP-статусы.

API используется frontend-приложением для взаимодействия с backend и управления проектами, досками, колонками и задачами.

## 2. Общие соглашения

- Базовый путь API: `/api/v1`.
- Формат обмена данными: JSON.
- Названия ресурсов в URL указываются во множественном числе.
- Идентификаторы ресурсов передаются в URL.
- Параметры фильтрации и поиска передаются через query-параметры.
- Ошибки API возвращаются в структурированном JSON-формате.
- Регистрация и авторизация пользователей не входят в MVP.

### 2.1. Используемые HTTP-методы

| Метод | Назначение |
|---|---|
| `GET` | Получение данных |
| `POST` | Создание ресурса или выполнение предусмотренной операции |
| `PUT` | Полное обновление ресурса |
| `PATCH` | Частичное обновление ресурса |
| `DELETE` | Удаление ресурса или выполнение операции удаления согласно правилам API |

### 2.2. Основные HTTP-статусы

| Статус | Значение |
|---|---|
| `200 OK` | Запрос выполнен успешно |
| `201 Created` | Ресурс создан |
| `204 No Content` | Запрос выполнен успешно, тело ответа отсутствует |
| `400 Bad Request` | Некорректные данные запроса |
| `404 Not Found` | Ресурс не найден |
| `409 Conflict` | Операция конфликтует с текущим состоянием данных |
| `500 Internal Server Error` | Внутренняя ошибка сервера |

## 3. Проекты

При создании проекта автоматически создаются связанная доска и три стандартные колонки: «К выполнению», «В работе» и «Готово».

| Метод | Эндпоинт | Назначение |
|---|---|---|
| `GET` | `/api/v1/projects` | Получить список проектов |
| `POST` | `/api/v1/projects` | Создать проект |
| `GET` | `/api/v1/projects/{projectId}` | Получить проект по ID |
| `PUT` | `/api/v1/projects/{projectId}` | Обновить проект |

Удаление проектов не входит в MVP.

## 4. Доски

| Метод | Эндпоинт | Назначение |
|---|---|---|
| `GET` | `/api/v1/projects/{projectId}/board` | Получить доску проекта |

Ответ должен содержать информацию о доске и её колонках, упорядоченных по позиции.

## 5. Колонки доски

| Метод | Эндпоинт | Назначение |
|---|---|---|
| `POST` | `/api/v1/boards/{boardId}/columns` | Создать колонку |
| `PUT` | `/api/v1/columns/{columnId}` | Переименовать колонку |
| `DELETE` | `/api/v1/columns/{columnId}` | Удалить колонку, если это разрешено правилами целостности |
| `PATCH` | `/api/v1/boards/{boardId}/columns/order` | Изменить порядок колонок |

## 6. Задачи

| Метод | Эндпоинт | Назначение |
|---|---|---|
| `GET` | `/api/v1/columns/{columnId}/tasks` | Получить активные задачи колонки |
| `POST` | `/api/v1/columns/{columnId}/tasks` | Создать задачу в колонке |
| `GET` | `/api/v1/tasks/{taskId}` | Получить задачу по ID |
| `PUT` | `/api/v1/tasks/{taskId}` | Обновить задачу |
| `PATCH` | `/api/v1/tasks/{taskId}/column` | Переместить задачу в другую колонку |
| `DELETE` | `/api/v1/tasks/{taskId}` | Выполнить мягкое удаление задачи |
| `GET` | `/api/v1/tasks/deleted` | Получить список мягко удалённых задач |
| `POST` | `/api/v1/tasks/{taskId}/restore` | Восстановить задачу |

## 7. Поиск и фильтрация

API должен поддерживать поиск задач по названию и фильтрацию по приоритету, колонке и исполнителю.

Точные query-параметры, форматы запросов и ответов будут описаны в следующих разделах спецификации.

## 8. Документирование ошибок

Ошибки должны возвращаться в JSON-формате с кодом ошибки и понятным сообщением. Ответы не должны содержать stack trace или внутренние сведения о реализации сервера.
